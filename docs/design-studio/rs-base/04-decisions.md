# 04 · Decisions for Shyam

Each lane builds on the **default**. Changing a default later means an RS-0 follow-up plus the work listed for it.
- R4 is fixed by Shyam (2026-10-18): "flexibility of choosing design and placing and editing content anywhere on the page".
- The rest are proposed defaults to accept or change.

| # | Question | Default (built) | If changed |
|---|---|---|---|
| R1 | Who uses the studio? | Admins and Managers create and edit. Only a Manager or Superadmin generates a final or approves a review (as KPI D11). Users (contributors) have no access. | Admins may finalise: a role change in RS-5 and RS-10. Contributors may comment: RS-10 adds a "commenter" view. |
| R2 | Who turns it on? | The Superadmin, per client: `company.report_studio_enabled`, default off. It needs KPI tracking on. The toggle sits next to the KPI toggle on the client's Overview tab. | On for every KPI client: drop the second switch. |
| R3 | Draft before the year is locked? | Yes. Drafts and proofs work at any time; pages show a "DRAFT" watermark and `VALUES_MISSING` warnings until the lock. A **final** needs the whole-year lock for the doc's sites (`kpi_period_lock`, period null, not reopened). | Allow finals without a lock: drop `YEAR_NOT_LOCKED`. Not recommended. |
| R4 | How free is editing? | **Fixed:** full free-form editing on free-form pages (any element, anywhere, move, resize, rotate, layer) plus self-paginating flow sections for long content (`01-contracts` §2). Designs and layouts are starting points, never constraints, except elements a template author locks (RS-10). | — |
| R5 | Editor engine | Our own DOM/SVG editor (RS-6): the sheet is drawn by our renderer, and an interaction layer handles selection, transforms and snapping. Libraries: `react-moveable` + `react-selecto` (MIT; RS-6 confirms the licence and React 19 support, otherwise a small custom layer). | Polotno SDK for free-form pages: licence by quote, charts only as regenerated SVG, its own PDF engine to merge. Needs a spike first. |
| R6 | Where does the AI run? | ESG-lite backend (`src/kpi/studio/ai/`), through the OpenRouter client already used by `src/reporting/ai-narrative.ts`. The python service is unchanged. | Move to python `app/report/`: adds a hop, but keeps all LLM code in one service. |
| R7 | Which models? | Env-configurable. Defaults: drafting (`draft_report`, `draft_page`, `leadership_draft`, `suggest_layouts`) uses `anthropic/claude-sonnet-5.5`. Rewrites, titles, alt text and checks use `google/gemini-3-flash-preview` (today's narrative default). Cover art uses the existing `imagery.ts` providers. | Single model everywhere: simpler, with a cost or quality trade-off. |
| R8 | AI budget | Per doc per day: $5, or 200 calls. Per company per month: $50. All configurable by the Superadmin per client. Over budget → `RS_AI_BUDGET_EXCEEDED`, and the studio keeps working without AI. | No cap: not recommended. |
| R9 | Materiality matrix | Optional scores: `impact_score` and `financial_score` (0–10) on `company_material_topic`, entered in a small block in KPI setup or in the wizard. The matrix layout is offered only when every material topic has both scores; otherwise a "material topics" list layout. The KPI D13 yes/no stays the source of `if_material`. | A full DMA module: a separate plan. |
| R10 | Correcting a final | Finals are frozen. A correction is a new final version (n+1) with a required note ("Restated: …"). The versions list shows both; the older one is marked "superseded". | Allow deleting a final (Superadmin, typed-name confirm): audit-logged. |
| R11 | Outputs | A4 portrait PDF (tagged, bookmarks). A share link, a 16:9 screen edition, interactive web and DOCX are out of scope for RS-M4. A 16:9 page size is a later design flag. | Add a 16:9 edition: a second page size in RS-1 and RS-3 layouts. |
| R12 | Fonts | A curated self-hosted set (OFL licence), subset at build time: Source Serif 4, Source Sans 3, DM Serif Display, IBM Plex Sans, IBM Plex Serif, Archivo, Fraunces, Noto Sans (Devanagari fallback). Brand stores a heading and body choice. No client font uploads. | Client font upload: needs a licence check per font and a subsetting pipeline. |
| R13 | Photos and images | Client uploads (R2, ≤ 10 MB; jpg, png, webp, and sanitised svg), plus AI images from `imagery.ts`. No stock-photo library. Images are downscaled to 300 dpi at their placed size for the final. | A stock-photo integration (Unsplash or Pexels API): attribution rules. |
| R14 | Language | English only. Indian number grouping (lakh/crore) is a number-format option. | Hindi or other languages: font fallback is ready (Noto). Needs translated layouts and an AI translate action producing a doc copy. |
| R15 | Concurrent editing | No real-time co-editing. Saving sends the whole doc with `rev` (optimistic). A conflict shows "Edited elsewhere: reload or keep mine (makes a copy)". The editor shows "Also open by another user" from a 30 s heartbeat. | Real-time (Yjs over websockets): a large separate module. |
| R16 | Small screens | Editing needs ≥ 1280 px. On 768–1279 px: view pages, open the Page view, comment. On < 768 px: download only. | A tablet editor: touch transforms in RS-6. |
| R17 | Accessibility of the PDF | Chromium tagged PDF and bookmarks from page names. Reading order is the order of the layers list (adjustable). Images need alt text (warning). Contrast is checked (error). veraPDF runs in CI as informational. | PDF/UA certification: Prince or DocRaptor for finals, as a separate engine. |
| R18 | What a final stores | Doc JSON, the resolved values for every binding and token (`data_snapshot`), `data_hash`, `design_version`, `renderer_hash`, the PDF and its SHA-256. A final always re-downloads the stored PDF, never a re-render. | — |
