# 04 · Decisions for Shyam

Each lane builds on the **default**. Changing a default later means an IN-0 follow-up plus the work listed for it.
All of these are proposed defaults to accept or change.

| # | Question | Default (built) | If changed |
|---|---|---|---|
| I1 | Who sees Insights? | Managers (their sites), Admins and Superadmins (client picker). Users (contributors) have no access. | Users see a read-only "My site" version: a scope variant in IN-1 and a nav entry. |
| I2 | Who turns it on? | The Superadmin, per client: `company.insights_enabled`, default off. The toggle sits next to the KPI toggle on the client's Overview tab. After IN-M2 has run on two clients for a month, flip the default to on (IN-0 follow-up). | On for everyone from day one: drop the switch, keep `IN_OFF` unused. |
| I3 | Is Insights a KPI feature? | No. It's a core page at `/insights`, works on emissions alone, and adds KPI panels when KPI tracking is on. | Make it KPI-only: move under `/kpi/insights`, gate with `requireKpiTracking`. Loses emissions-only clients. |
| I4 | Does it replace Overview, `/kpi/dashboard` or `/kpi/esg`? | No. Those stay as working pages (approvals, gaps, reminders). Insights is the summary and story; each panel links to the working page behind it. | Replace `/kpi/esg` with Insights: redirect and move its heat table into Insights. |
| I5 | Where is it in the nav? | Second item, under "Overview", for Manager and Admin. Overview stays the home page. | Make Insights the Manager home: change the default route; Overview becomes "Operations". |
| I6 | Target status thresholds | For a target: `expected_pct` = straight-line share of the way from baseline year to target year at today's date. `on_track` if progress ≥ expected; `at_risk` if behind by ≤ 10 pp; `off_track` if behind by > 10 pp; `reached` if progress ≥ 100. SBTi pathway: on_track if actual ≤ pathway, at_risk ≤ +5 %, off_track > +5 %. | Per-client thresholds: a settings block and a column. |
| I7 | Decoupling base and units | Base year = the SBTi base year if set, else the first year with both approved emissions and production. Output index per site in its own unit, combined by base-year emission weight. If any site lacks production data, the output series is `combined_output: true` with a note. | Revenue as the activity measure: needs a revenue KPI or input; add `activity=revenue`. |
| I8 | Bridge method | Additive LMDI (log-mean Divisia), zero residual. Drivers: activity (output), Scope 1 intensity, Scope 2 energy intensity (kWh per output), Scope 2 grid and renewables (tCO₂e per kWh), Scope 3 (as one block). Missing inputs fold that scope into `other` with a note. | Simple sequential substitution: easier to explain but order-dependent; or split Scope 3 by category (needs per-category activity). |
| I9 | Flow (Sankey) widths | Sites → scopes → GHG KPIs in tCO₂e. KPIs → disclosures as counts (one unit per mapping, `fit` shown by link style), drawn muted with its own legend. Without KPI tracking: sites → scopes → top categories. | Hide the disclosure column entirely: simpler, loses the "one entry, many disclosures" story. |
| I10 | Materiality scores | Same columns and endpoint as RS-2 (`impact_score`, `financial_score`, 0–10). Whichever of IN-7 or RS-2 merges first ships `migrate:rs-materiality-scores`; the other reuses it. Without scores the panel shows a topic list with status and a link to add scores. | A full DMA module with stakeholder scoring: a separate plan. |
| I11 | Caching | Per panel, keyed by (company, sites, period, stamp). Stamp = max(approved_at) of emissions and KPI values in scope, plus `insight_event.updated_at`. TTL 10 min; ETag on responses. | No cache: simpler, slower on big clients. |
| I12 | Card rules and thresholds | The 11 rules in `01-contracts` §6, thresholds fixed in `rules/thresholds.ts`. At most 6 cards, ranked critical → attention → good → info. | Per-client thresholds or user-defined rules: out of scope (I15). |
| I13 | Where does the AI run? | ESG-lite backend (`src/insights/ai/`), through the same OpenRouter client as `src/reporting/ai-narrative.ts`. Model: `google/gemini-3-flash-preview` (cheap rewording). Off by default per user; a toggle on the cards. | Python service: adds a hop. Or no AI at all: drop IN-9. |
| I14 | AI budget | Per company per month: $10 or 2,000 calls; cards cached per (rule, params) for the stamp's life. Over budget → `IN_AI_BUDGET`, rule text shown. | No cap: not recommended. |
| I15 | Out of scope | Custom layouts and drag-drop dashboards, peer benchmarks, user-defined rules, scheduled email digests, real-time updates, a mobile-only layout beyond 390 px responsiveness. | Each is its own plan. |
| I16 | Present mode and PDF | `/insights/present`: full-screen, one story panel per slide, arrow keys, same filters. PDF snapshot: A4 landscape, one page, hero + four story panels + cards, rendered by the existing Playwright printer from a print route. Report studio hand-off ("Add to report") waits for RS-M2 and is not in this plan. | Add "Add to report" now: depends on RS-1 chart kinds (`waterfall`, `sankey`, `materiality_matrix`, `target_bars` already in RS contracts). |
