# E1 claim

Module: E1 (PCF track) · PCF data model, calculation engine and API. Spec: `docs/pcf/foundation/E1-data-and-engine/CLAUDE.md`; golden file from PCF-0: `docs/pcf/phase0/pilot-golden.json` (method rules in `docs/pcf/phase0/method-note.md`).

Plan, five PRs into `redesign/integration`, each additive:
1. **Entities + migration**: `PcfStudy`, `PcfInput`, `PcfAllocation`, `PcfResult`, `MaterialFactor`; `Product` gains `declared_unit`, `declared_unit_qty`, `mass_per_unit_kg`, `pcr_tag`; idempotent `migrate:pcf` script (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`); entities registered in the data source. No existing column changes.
2. **computePcf**: pure function in `src/pcf/engine/` with stage unit tests (A1 recycled split, A2 tonne.km, A3 allocation with 1 and many products, packaging, waste, cut-off, primary share, DQR), a golden test against `pilot-golden.json` (every expected value within ±0.5%), and byte-identical regeneration from `factor_snapshot`. Run by a new `test:unit` script wired into CI.
3. **API routes** `/pcf/*` (manager, company-scoped; superadmin all): studies CRUD (draft-only edits), PUT inputs, calculate, submit/approve/reject/publish (approver ≠ creator), material factors CRUD; User role gets 403 on every `/pcf/*` route; API tests in `ci/api/tests/`.
4. **Allocation preview + reconciliation**: A3 from approved Scope 1+2 `Emission` rows and approved `ProductionData` for the study's site and period; `/pcf/reconciliation`.
5. **Staleness**: hook in the existing emission/production approve and edit paths marks approved studies that used those rows as stale and notifies the owner. `Completes: E1`.

A PCF result is never exposed or reused as a CBAM figure.
