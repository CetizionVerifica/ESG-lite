When you send a row that matches one already saved for the same site, category and period, ESGLite stops and asks what to do instead of saving a copy.

**What you see**
In the review step, the row reads "Already entered for this period" with a **Replace or skip** button. The dialog "N rows are already entered for …" lists each row with the new total, the saved total, the saved entry's status and who entered it.

**Your choices for each row**
- **Replace**: swaps the saved entry for your new one.
- **Keep both**: saves your row as another entry. Use this for a genuine second bill in the same month. Your manager sees the two as a possible duplicate.
- **Skip**: keeps the saved entry and drops your new row. This is the default.

**Replace all**, **Keep both for all** and **Skip all** set every row at once. Then choose **Apply**. **Decide later** closes the dialog without sending those rows.

**When you can't replace**
**Replace** is switched off when:
- someone else entered the saved entry ("… entered this, so you can't replace it"), or
- the saved entry is already approved ("It's already approved, so you can't replace it").

Choose **Keep both** or **Skip** instead. If the saved entry is wrong, ask your manager.

**The same file on two entries**
If a file you attached is already the evidence of another entry for the period, the review step warns "This evidence already backs another entry". If it's the same purchase, it would be counted twice. You can still send.

**Avoiding duplicates**
Check the list of what's already entered under Add data before you type. To change a Pending entry, use **Edit** there or in [My entries](/data/mine) instead of entering it again.
