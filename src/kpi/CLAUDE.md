# src/kpi (ESG-lite) — KPI tracking backend layer

> Layer spec. Goes to `ESG-lite/src/kpi/CLAUDE.md`. Read it after the root CLAUDE.md, `docs/kpi/00-plan.md`, `01-contracts.md` and `04-decisions.md`, and before your module folder's CLAUDE.md.

## Rules
1. **The switch first.**
   - Every route in `router.ts` runs `authenticate` then `requireKpiTracking`, which answers 403 `KPI_TRACKING_OFF` when the caller's company has `kpi_tracking_enabled = false`.
   - The exceptions are `GET /kpi/status`, which reports the state, and `/kpi/library/*`, which is Superadmin only.
   - A Superadmin acting for a client passes `company_id`, and the guard checks that company.
2. **Same access as emissions.**
   - Sites come from `accessibleSiteIds` (`src/utils/companyScope.ts`); topics from `kpi_topic_grant` (empty = all).
   - Contributors write only KPIs assigned to them (`kpi_assignment`) or, with no assignment, on their own site.
   - Managers review their sites. Admins set up and enter company-level values. Superadmin can do everything.
   - Another company's ids answer 404, never 403.
3. **Company scoping in SQL.** Every query filters by the caller's `company_id`; library rows (`company_id IS NULL`) are readable by all, writable by Superadmin only.
4. **No emission maths here.** Auto KPIs call the reporting functions (`computeGhgTables`, `computeScope3`, …) or read approved emission rows' stored totals. Don't change `src/reporting/*` or `src/services/emissionWrite/*` for KPIs; ask for a follow-up in their owners' plans instead.
5. **Units.**
   - Values are stored as entered (`value_numeric`, `unit`) and canonical (`value_canonical`).
   - Conversions use `src/services/emissionWrite/units.ts` (`getConversionFactor`, `canonicalUnit`), extended in `values/units.ts` for water, mass and count where needed.
   - Never guess a conversion: an unconvertible unit is `KPI_UNIT_NOT_ALLOWED`.
6. **Periods.**
   - A value's period comes from the KPI's frequency and the company's year type (`companyYearType`, FY start month 4 as `src/reporting/ghg-data.ts`).
   - Writes into a locked KPI period answer `KPI_PERIOD_LOCKED`. Locks are separate from the emissions `period_lock`.
7. **Status flow.**
   - Draft → Pending (submit) → Approved/Rejected (Manager). A contributor's edit of a Rejected value makes it a Draft.
   - Drafts are visible to their author and to Admins of the company, never in reviews, dashboards or reports.
   - Reports and exports read **approved** values only.
8. **Audit.**
   - Every write records an `audit_log` row (`entity_type` `kpi_*`) with old and new values and the reason when there is one.
   - Logs carry ids and codes, never values typed by users or document contents.
9. **Validation** with the zod schemas from `contracts/schemas.ts`. Errors use the `{code, message, details}` shape and the codes in `contracts/errors.ts`.
10. **Tests every module adds:** tenant isolation, role matrix, switch-off (`KPI_TRACKING_OFF`) for each endpoint, every new error code, migrations run twice, and its golden cases switched from `skip` to `run`.

## KPI-1 as built

## KPI-4 as built

Unique keys that treat null as a value are expression indexes (`UQ_kpi_value_company_site_kpi_period` on COALESCE(site_id, 0); `UQ_kpi_period_lock_company_site_year_period`), mirrored in `ci/api/fixture.sql`. Additions to 01-contracts §2: `kpi_value_evidence.public_id` (stored file id, for removal), `kpi_period_lock.year_type` (how `year` reads; `period` is a calendar month 1–12 or null for the whole year).
- `values/period.ts` (pure): CY / FY (FY 2026 = Apr 2025–Mar 2026), monthly / quarterly / annual, labels (`Sep 2026`, `Q1 FY2025-26`, `FY2025-26`), `dueDate` (due_day of the next month, clamped).
- `values/units.ts`: spellings through the engine's `canonicalUnit`, then a KPI registry by dimension and family (energy, mass, CO2e, volume incl. kL/ML, count, days, %, injury rates, time, same-currency scales). Cross-family → `KPI_UNIT_NOT_ALLOWED`. Factors are exact (the engine's table rounds GJ↔kWh).
- `values/aggregate.ts` (pure): sum / average / max / latest / weighted_average / none; missing ≠ 0 (`missing`, `complete`, `missing_periods`, `missing_sites`); `WEIGHT_KPI` (LTIFR by HOURS_WORKED).
- `values/service.ts`: `upsertDrafts` (per-item transaction and result), `submit`, `listValues`. The KPI-3 hooks (`isKpiSelected`, `companyKpiYearType`, `companyKpiFrequency`, `assertCanWrite`, `needsEvidence`) read the setup since KPI-3 (see below).
- Writes hold `pg_advisory_xact_lock_shared(KPI_LOCK_CLASS = 4150, company)`; KPI-8's lock takes it exclusively.
- Pending and approved values aren't editable (`KPI_NOT_DRAFT`); someone else's draft answers `KPI_NOT_DRAFT` on save and 404 elsewhere. Approved values: only Manager/Admin/Superadmin change evidence; a removal is audited as `evidence_removed_after_approval`.
- Audit actions on `kpi_value`: create, update, reopen (rejected → draft), submit, evidence_added, evidence_removed, evidence_removed_after_approval.

## KPI-3 as built
- Tables `company_kpi_settings` (pk company_id; + `updated_by`, `created_at`, `updated_at`), `company_framework` (+ `framework_code`, so `UQ_company_framework_company_code` holds "one version per framework code"), `company_material_topic`, `company_kpi` (+ `updated_by`, `updated_at`), `kpi_assignment` (+ `created_at`, `updated_at`; unique `UQ_kpi_assignment_company_kpi_site` on (company, KPI, COALESCE(site, 0)), an expression index mirrored in `ci/api/fixture.sql`), `kpi_topic_grant` (migrate:kpi-setup, `src/scripts/migrateKpiSetup.ts`).
- `setup/settings.ts`: the reads other modules use (`kpiSettings` with defaults: year type prefilled from the company's emission rows, else CY; `setupCompleted`, `companyKpiRow`, `enabledFrameworks`, `assignmentFor`, `topicGrants`, `userSiteIds`).
- `setup/recommend.ts` (pure): recommended = maps to a disclosure of an enabled version that is `required`/`core` (an ESRS one with a topic marked not material doesn't count) or `if_material` with its topic material; formula inputs pulled in transitively (`pulled_in_by`). Undecided topics aren't material.
- `setup/service.ts`:
  - `GET /kpi/setup` (any role) → `{settings, frameworks, material_topics, kpis, assignments, recommended (kpi_definition_ids), recommended_reasons ([{kpi_definition_id, code, reasons, pulled_in_by}]), available_frameworks, sites}`; Admin/Superadmin also get `people` (id, name, role, site_ids; no emails), `topic_grants`, `suggested_assignments` (default owners: the site's first User, reviewer null = the site's managers; company level → the first Admin; manual KPIs only).
  - `PUT /kpi/setup` (Admin, Superadmin; else 403 `KPI_FORBIDDEN`): any subset of `settings` (`year_type`, `first_year`, `due_day` 1–28, `complete`), `frameworks` (ids; `framework_ids` accepted too), `material_topics`, `kpis`, `assignments`, in one transaction under advisory lock (4152, company); answers the GET shape. Each changed step writes an audit row (`kpi_setup`, entity_id = company, actions `settings`, `frameworks`, `material_topics`, `kpis`, `assignments`, `complete`).
  - Rules: one version per framework code (`KPI_VALIDATION`); not material without a reason and a recommended KPI left out without a reason → 400 `KPI_REASON_REQUIRED` (`details.esrs_topic` / `details.kpi`); owner not a user of the site (company for company level) or reviewer not a Manager of the site → 422 `KPI_VALUE_INVALID` (`details.rule` `user_of_the_site` | `user_of_the_company` | `manager_of_the_site`); another company's site or KPI → 404; assigning an unselected KPI → `KPI_NOT_SELECTED`; level/site mismatch → `KPI_VALIDATION`; the year type can't change once values use the other one (`KPI_VALIDATION`); an omitted `frequency` keeps the override, null clears it. The `kpis` step replaces the selection: a KPI selected before and not listed is left out (a recommended one must be listed with `selected:false` and a reason, else `KPI_REASON_REQUIRED`). `settings.complete: true` needs a framework and a selected KPI (409 `KPI_SETUP_INCOMPLETE`, `details.missing`) and sets `setup_completed_at` once.
  - `POST /kpi/setup/custom-kpis` (Admin, Superadmin) → 201 `{definition}` (+ `mappings`): `code` optional (made from the name, `C<company>_<NAME>`, `_2`… when taken; a library code → `KPI_CODE_TAKEN`), `source` manual (default) or formula, checked like library KPIs (`checkDefinition(m, d, selfId, companyId)`), selected at once, mappings into `kpi_disclosure_map` for the company's KPI.
- `PATCH /company-admin/users/:id {kpi_topics: KpiTopic[]}` (Admin; `setup/topicGrants.ts`): replaces the user's grants (audited `topic_grant`), answers `kpi_topics`; 403 `KPI_TRACKING_OFF` when the switch is off; bad topics → 400 `KPI_VALIDATION`.
- Wired into KPI-4: `GET /kpi/status.setup_completed`; value writes and submits need a finished setup (409 `KPI_SETUP_INCOMPLETE`; reads still answer); only selected KPIs take values; an item's `frequency` / `year_type` must be the company's (`KPI_VALUE_INVALID` `company_frequency_<f>` / `company_year_type_<t>`); BRSR Core evidence only when the company enabled that BRSR version; `assertCanWrite`: Admin/Superadmin all; the assigned owner; Managers their sites and company level; Users only unassigned site-level pairs on their sites in their topics. `GET /kpi/catalogue` shows the enabled versions (all active ones until the company enables one).
- `POST /kpi/setup/invite` (Admin, Superadmin) → `{notified}`: one `kpi_assigned` notification ("You have KPIs to enter", link `/kpi`) per owner of an assignment of a selected KPI; audited `invite`. `kpi_assigned` was added to `KPI_NOTIFICATION_KINDS` (in 01-contracts §3 since the wave C KPI-0 follow-up).

## KPI-6 as built
- `formulas/parse.ts` (pure): a recursive-descent parser, no `eval`: KPI codes, numbers (`1.5e3`), `+ - * /` (and `× ÷ −`), brackets, unary minus, `CODE.part` (breakdown), `sum(CODE)` / `avg(CODE)` over sites. Errors: 422 `KPI_FORMULA_INVALID` `{problems:[text], position}` (0-based). `formulaCodes` (refs, [] when invalid). Units: `parseUnit` (`tCO2e per INR crore` → {tCO2e:1, INR crore:-1}; spellings through the unit registry; %, ratio, count and per-person words are dimensionless), `unitOf` (+/− need the same unit, ×/÷ combine), `formatUnit`.
- `formulas/graph.ts` (pure): `formulaProblems` (syntax, unknown codes, result unit ≠ the KPI's canonical unit, cycles), `definitionProblems` (only problems a save brings: its own, a cycle through it, a formula that uses it losing its unit), `dependantsOf`, `evaluationOrder` (inputs first; cycles never evaluated). Used by `library/service.ts` `checkDefinition` for library and custom KPIs.
- `formulas/evaluate.ts` (pure): `evaluate(ast, resolve)` → `{value, reason: null | "missing_inputs" | "division_by_zero", missing, waiting_for, inputs}`; a missing input is never 0; 12 significant digits.
- `formulas/resolve.ts` (pure): a reference for a site (or the company) and period P: the input's submitted values inside P at the input's own company frequency, rolled up over periods by its aggregation; company target = company-level value, or site values rolled up over the sites that have one (`sum()` adds, `avg()` averages, weighted average → plain average); a site-level formula reads a company-level input's company value; gaps make it `partial`, nothing at all makes it missing; status approved only when every value used is.
- `formulas/recompute.ts`: `recomputeFormulas(company, {years, changedCodes?})` for selected formula KPIs (library and the company's own), every period of the year, per site or company; inputs are pending or approved values (drafts and rejected don't count). Writes through `values/system.ts` (`source:'formula'`, `entered_by` null, `status` approved when every input is, else pending with `comment` "Waiting for <names>."; `auto_snapshot` = `{kind:'formula', formula, unit, inputs:[{code, part, fn, value, unit, status, partial}], waiting_for, computed_at}`); no value → a stored one is removed (`formula_removed`); locked periods untouched. `recomputeForValues(company, valueIds)` runs after `POST /kpi/values/submit` and after KPI-8's approve and reject (never fails them).
- `values/system.ts` (KPI-4's system writer): `writeSystemValue` / `removeSystemValue`, each its own transaction with the KPI lease; skip locked periods and manual values with the same key; audit `auto_refresh` / `formula_recompute` / `auto_removed` / `formula_removed` (changed_by null); a write that only changes the read time keeps the row, but clears a held `checks` (KPI_AUTO_STALE).
- Formula values are read-only: `PUT /kpi/values` → `KPI_AUTO_READ_ONLY`; submit → `KPI_NOT_DRAFT`.
- Golden cases: `ci/golden/kpi/formulas.json` (GHG intensity per revenue, energy per tonne, water consumption, women in the workforce %, a missing input, division by zero), run by `ci/unit/kpi-formulas.test.cjs`; the FE preview runs the same file.
- No HTTP route of its own (01-contracts §3 has none).


## KPI-5 as built
- `auto/` holds one adapter per `AutoSourceKey` (`adapters.ts`; `ghg_scope3_category_n` expands to 1–15). An adapter takes `{companyId, siteIds, period, kpi}` and gives `{value_canonical, unit, breakdown?, snapshot}`, or null when its source has nothing (no value; never 0).
  - `ghg.ts`: `ghg_scope1` / `ghg_scope2_location` = `computeGhgTables(filters).totals[year].scope1 / .scope2`; `ghg_scope3_total` = `computeScope3(filters, company).total_tco2e`; `ghg_scope3_category_<n>` = its row's `tco2e`. Filters are the report's (`ghgFilters`: sites, year type, year, month or quarter). The only SQL counts the approved rows behind a figure for the snapshot (`rows`, `row_ids` ≤ 200). `ghg_scope2_market` gives no value: ESGLite records location-based Scope 2 only.
  - `energy.ts`: approved Scope 2 rows, Scope 1 combustion rows (category named for combustion/fuel) and no-scope renewable rows; quantity via `pickActivityValue`, unit = `activity_data_unit` or the factor's denominator; energy units convert directly, fuels by mass or volume through the snapshot's `ncv` (GJ per `ncv_unit`) or `data/kpi/ncv.json` (IPCC 2006 NCVs, typical densities; `verified: false`); unconvertible rows are `skipped` with a reason. Renewable split by `data/kpi/renewables.json`.
  - `production.ts`: approved `production_data` whose whole period lies inside the KPI period, in the canonical unit, breakdown `product_<id>`; any unconvertible unit → no total, products listed.
  - `waste.ts`: approved Scope 3 category 5 rows in the canonical unit; breakdown by disposal method from the activity name when every row names one of the KPI's breakdown values.
- `auto/refresh.ts` `refreshAuto(company, year)`: selected auto KPIs × sites (or the company) × periods of the reporting year that have started; writes through `values/system.ts` (`source:'auto'`, `status:'approved'`), removes values whose source has gone, leaves locked periods; then recomputes every formula of the year (KPI-6). One refresh per company at a time (in process). 409 `KPI_SETUP_INCOMPLETE` before setup.
- `POST /kpi/auto/refresh?year=` (Manager, Admin, Superadmin; User 403 `KPI_FORBIDDEN`; `year` required) → `{year, refreshed, unchanged, removed, locked, values, formulas: {written, unchanged, removed, locked}}`; `values` are the year's auto values on the caller's sites.
- `auto/hook.ts` `kpiSourceChanged(kind, ids)`: called next to every `pcfDataChanged` in the emission, production, category and product controllers (after approve, reject and edit; before deletes, while the rows exist). For companies with the switch on it holds the affected auto values (same site or company level, period covering the row's date, only the auto sources the row's scope can feed) with `checks = {ready:false, held:["KPI_AUTO_STALE"], checked_at}`, and schedules a debounced refresh (60 s after the last change, `KPI_AUTO_REFRESH_DELAY_MS`; off under NODE_ENV=test unless set). A refresh clears the hold. Never throws.
- Golden cases: `ci/golden/kpi/auto.json` (Scope 1 and 2 equal `POST /user/ghg/tables`, Scope 3 total and a category equal `GET /reports/ghg/scope3`, energy from diesel litres and kWh by hand, production, waste with its method, a refresh after rejecting one row), run by `ci/api/tests/kpi-5-auto.test.cjs`. Nothing in `src/reporting` or `emissionWrite` changed.

## KPI-8 as built (review and close)
- KPI-0 follow-up first: 01-contracts §3 gained `POST /kpi/setup/invite`, the notification kinds table (`kpi_enabled`, `kpi_assigned`, `kpi_submitted`, `kpi_rejected`, `kpi_due`) and the bulk/wrapping conventions; §4 lists the plumbing codes, including the per-id review refusals `KPI_NOT_PENDING` (409), `KPI_NOT_READY` (409) and `KPI_SELF_REVIEW` (403); `KpiValueChecksSchema` gained optional `details`.
- `review/checks.ts`: `computeChecks` (pure) and `storeChecks(m, id)`. `kpi_value.checks = {ready, held, info, details?, checked_at}`. KPI_EVIDENCE holds every manual value without evidence (D15; BRSR Core can't even be submitted without it), KPI_CHANGE_LIMIT compares with the same period last year (pending or approved) against `emission_threshold.threshold_percentage` (default 5; `details {previous, change_pct, ratio, limit_pct}`), KPI_BREAKDOWN_SUM ±0.5 % of the total as entered (`details {parts, total, difference_pct}`), KPI_UNIT_CONVERTED info only, KPI_ESTIMATE, KPI_AUTO_STALE kept from KPI-5's hold. Stored on submit, on evidence add/remove of a pending value, again at approve/reject, and on read by `GET /kpi/values` for a pending manual value that has none.
- `review/approve.ts` `PUT /kpi/values/approve {ids, only_ready?}` and `PUT /kpi/values/reject {ids, reason}` → `{updated, refused:[{id, code}]}`. Manager (their sites and company-level values) and Superadmin; Admin and User → 403 `KPI_FORBIDDEN`; reject without a reason → 400 `KPI_REASON_REQUIRED`. Per id under the KPI lease: not visible → `KPI_NOT_FOUND` (incl. someone else's draft and another company's id), auto/formula → `KPI_AUTO_READ_ONLY`, approve needs pending and reject pending or approved → `KPI_NOT_PENDING`, the caller entered it → `KPI_SELF_REVIEW` (the Superadmin may, as `scope.middleware` `selfReview`), locked → `KPI_PERIOD_LOCKED`, `only_ready` and held → `KPI_NOT_READY`. Sets `reviewed_by/at`, `review_comment` (the reason on reject); audit `approve` / `reject` (reason in `audit_log.reason`). Then `recomputeForValues`; a reject sends `kpi_rejected` (one per person who entered, `meta {reviewer, reason}`, link `/kpi`).
- `review/notify.ts`: `kpi_submitted` after `POST /kpi/values/submit`, one per reviewer per submit (the assignment's `reviewer_user_id`, else the site's Managers; company level: the company's Managers; never the submitter), link `/data/approvals?view=kpi`.
- `review/lock.ts`: `GET /kpi/periods/lock?year=&period=&site=` → `{company_id, year, period, year_type, label, range, sites:[{site_id (null = the "Company" row), name, locked, lock, reopened, kpis:[{kpi_definition_id, code, name, periods, counts:{missing,draft,pending,approved,rejected}, missing}], left}], left:[{site_id, site_name, kpi_definition_id, code, kpi_name, period_start, period_label, reason, value_id}], can_lock, locked}`. `POST /kpi/periods/lock {year, period?, site_id?}` and `POST /kpi/periods/unlock {…, reason}` → `{lock, status}`. Expected = selected manual KPIs × targets × their periods ending in the range (company-level KPIs on the Company row; site-level on the sites they're assigned on, else every site: `expectedSites`, shared with KPI-10); auto and formula values never hold a period open. Managers: own sites, `site_id` required to write (company-wide → 403); Admin/Superadmin: a site or the company (`site_id` null: one lock row with `site_id` null). Lock re-checks under `pg_advisory_xact_lock(KPI_LOCK_CLASS, company)` (writes hold it shared) → 422 `KPI_PERIOD_INCOMPLETE {left}`; idempotent; a reopened row is reused. Unlock: exact scope, else 404 (`details.locked_by` names a wider lock). Audit `kpi_period_lock` `lock` / `unlock` (reason).

## KPI-10 as built (dashboard)
- `dashboard/coverage.ts` (pure): a disclosure counts when `required`/`core`, or `if_material` with its ESRS topic material (undecided = not material); `voluntary` is shown, never counted. Answering KPIs = exact/partial fits, else derived ones. A KPI not selected with a reason is excluded; without one it's "not tracked" (missing). Disclosure state: excluded (every answering KPI excluded, or topic not material; listed in `excluded_disclosures` with `reason_kind` not_material | excluded and the reason) → missing (any missing or not tracked, or nothing mapped) → pending → approved (all) → not_due. `percent = round(approved / counted × 100)`; BRSR `core {done, total}` over counted core disclosures.
- `dashboard/service.ts` `GET /kpi/dashboard?year=&framework=&site=&topic=` (Manager, Admin, Superadmin; User 403 `KPI_FORBIDDEN`; 409 before setup; a site outside the caller's scope 404) → `{year, year_type, label, filters, coverage:[{framework, framework_id, version, required, approved, pending, missing, not_due, excluded, percent, core, gaps, disclosures:[{disclosure_id, code, title, section, requirement, state, kpis, reason_kind?, reason?}], excluded_disclosures}], gaps:[{kpi_definition_id, code, kpi_name, topic, site_id, site_name, periods_missing, period_labels, owner_user_id, owner_name, link}], cards:[{kpi_definition_id, code, name, topic, source, level, unit, decimals, value, complete, previous, change_pct, status (approved | partial | none), pending, series:[{period_start, label, value}] (12), target {id, target_year, target_value, direction, progress_pct, status, achieved} | null}], pending_not_in:{kpi_values, kpi_value_ids (≤200), emission_rows, link}}`.
  - KPI state: manual KPIs need an approved value for every target × every period of the year that has ended (targets: company; or `expectedSites` — the sites it's assigned on, else every site in scope); auto/calculated KPIs count the values that exist (none = missing); nothing due yet = not_due. Gaps: manual KPIs × targets with ended periods that have nothing submitted (missing, draft, rejected), owner from the assignment; `topic`, `framework` and `site` narrow them. Cards: selected numeric KPIs (company-level ones hidden under a site filter), figures from approved values via `values/yearly.ts`, target from KPI-9 (`targetsWithProgress`; the nearest target year from the selected year on). `framework` limits cards and gaps to KPIs answering its counted disclosures. `pending_not_in.emission_rows` counts pending emission rows of the year on the sites in scope (D14).
- `dashboard/remind.ts` `POST /kpi/dashboard/remind {kpi, site}` (Manager, Admin, Superadmin) → `{sent, notified, already_today}`: `kpi_due` ("Reminder: KPI values due", `meta {kind:"remind", kpi, site, kpi_definition_id, site_id, by}`) to the assignment owner, else the site's Users with the KPI's topic, or (company level) the company's Admins; at most once a day per person and item (`alreadyReminded`). Refusals: not selected `KPI_NOT_SELECTED`, auto/formula `KPI_AUTO_READ_ONLY`, level/site mismatch or nobody owes it `KPI_VALUE_INVALID`, site/KPI outside scope 404.
- Tests: `ci/unit/kpi-dashboard.test.cjs`, `ci/api/tests/kpi-10-dashboard.test.cjs` (coverage worked by hand for GRI, BRSR + Core, ESRS + materiality).
